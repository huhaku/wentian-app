## 3. 当前主题与视觉原则

### 3.1 视觉原则
1. 保持信息层级清晰
2. 保持头部区域与卡片区域区分明确
3. 真实 API 接入不破坏现有 UI 布局
4. 错误态和正常态都要保持统一设计语言

### 3.2 当前风格特征
- 蓝色系顶部背景
- Material Design 3 卡片
- 圆角设计
- 轻量阴影
- 大字号温度展示
- 预报信息采用紧凑列表布局

## 4. WeatherScreen 组件规范

### 4.1 页面职责
`WeatherScreen` 负责：
- 展示天气数据
- 展示加载态 / 错误态
- 打开设置
- 跳转城市选择

### 4.2 页面状态
| 状态 | 表现 |
|------|------|
| Loading | 显示加载中 |
| Success | 显示完整天气信息 |
| Error | 显示错误信息与配置表单 |

### 4.3 成功态结构
```text
WeatherScreen
├── 顶部渐变天气头部
├── 当前天气卡片
├── 24 小时预报区域
├── 7 天预报区域
└── 其他天气信息区域
```

### 4.4 错误态结构
```text
ErrorContent
├── 错误信息文本
├── 复制能力
├── API URL 输入框
├── API Key 输入框
└── 保存并重试按钮
```

### 4.5 错误态规范
- 错误信息必须可复制
- 错误页允许直接修改配置
- 用户修正配置后可立即重试
- 错误页不应只给出不可操作提示

## 5. 城市选择页面规范

### 5.1 页面职责
`LocationSelectionScreen` 负责：
- 展示已添加城市
- 搜索城市
- 处理搜索结果、空态和错误态
- 标记默认城市

### 5.2 搜索状态规范
| 状态 | 表现 |
|------|------|
| Idle | 展示已添加城市 |
| Loading | 展示加载中 |
| Success(有结果) | 展示搜索结果 |
| Success(空结果) | 展示“未找到相关城市” |
| Error | 展示错误信息与重试入口 |

### 5.3 交互规范
1. 输入关键词后触发搜索
2. 搜索无结果时显示空态，不显示 400 报错
3. 默认城市要有明确标记
4. 城市列表和搜索结果的卡片样式保持一致

## 6. 设置弹窗规范

### 6.1 当前职责
`SettingsDialog` 当前主要承担“运行时配置”能力，而不是完整产品设置中心。

### 6.2 当前配置项
- 刷新间隔
- API URL
- API Key

### 6.3 规范要求
1. 输入框文案必须清晰
2. 与错误页使用一致的配置概念
3. 保存后应能立即生效或可立即触发重试

## 7. 预报组件规范

### 7.1 24 小时预报
- 使用横向滚动布局
- 每项展示时间、天气图标、温度
- 布局紧凑，适配小屏

### 7.2 7 天预报
- 使用纵向列表卡片布局
- 每行固定展示：星期、月日、图标、描述、温度
- 星期必须根据真实日期计算
- “今天”优先显示在首项

---

## 8. 组件实现约束

### 8.1 一致性约束
- 不随意改变现有 UI 风格
- 真实 API 接入只替换数据来源，不重构视觉结构
- 新增表单或错误处理时保持与主界面一致的设计语言

### 8.2 文案约束
- 所有文案使用简体中文
- 错误文案尽量可操作、可恢复
- 搜索空态与真正异常必须区分

### 8.3 状态管理约束
- Compose 页面状态统一通过 ViewModel + StateFlow 管理
- UI 收集状态使用 `collectAsStateWithLifecycle()`
