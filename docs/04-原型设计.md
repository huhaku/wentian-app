# Android 天气应用原型设计

## 1. 设计概述

当前应用已经从早期静态原型阶段进入可运行产品原型阶段。文档此处不再只描述理想界面，而是同步当前实际界面形态与交互规则。

设计目标：
- 简体中文界面
- 天气信息层次清晰
- 保持现有主界面视觉风格不被接口接入破坏
- 支持错误恢复、城市搜索、设置配置与桌面小部件

---

## 2. 当前视觉风格

### 2.1 设计关键词
- 蓝色系渐变头部
- Material Design 3
- 圆角卡片
- 轻量阴影
- 信息分区清晰
- 适合单手操作

### 2.2 已落地的主界面结构

```text
主天气页
├── 顶部渐变区域
│   ├── 城市
│   ├── 设置入口
│   ├── 当前温度
│   ├── 天气状况
│   └── 风向/湿度/气压等概览
├── 当前天气卡片
├── 24 小时预报卡片
├── 7 天预报卡片
└── 其他补充天气信息
```

### 2.3 当前小部件视觉
- 已支持多尺寸
- 显示时间、日期、天气信息
- 遵循 Android Widget 基本布局规范

---

## 3. 当前页面原型说明

### 3.1 主天气页面
当前页面已实现：
1. 顶部城市信息与设置入口
2. 当前天气核心信息展示
3. 24 小时预报横向列表
4. 7 天预报纵向卡片列表
5. 空气质量内容展示

#### 当前交互
- 点击位置区域进入城市选择
- 点击设置图标打开设置弹窗
- 页面支持天气状态切换（加载 / 成功 / 错误）

### 3.2 错误页面
这是当前实现中非常关键的一页，早期原型文档未完整体现。

当前错误页已支持：
- 展示错误信息
- 错误信息可复制
- 输入 API URL
- 输入 API Key
- 点击“保存并重试”

适用场景：
- API Key 未填写
- API Key 错误
- 网络异常
- 接口解析异常

### 3.3 城市选择页面
当前页面为 `LocationSelectionScreen`，而不是早期拆分的独立“位置页 + 搜索页”双页方案。

页面内容：
- 标题栏
- 搜索框
- 已添加城市列表
- 搜索结果区域 / 空状态 / 错误状态
- 默认城市标记

当前默认城市：**广东省广州市**。

#### 当前交互
- 输入关键词后发起城市搜索
- 搜索无结果时显示“未找到相关城市”
- 不再因为无结果返回 400 报错
- 点击城市可切换当前展示城市

### 3.4 设置弹窗
当前不是完整独立设置页，而是 `SettingsDialog`。

已支持：
- 刷新间隔设置
- API URL 设置
- API Key 设置

暂未实现：
- 主题切换
- 温度单位切换
- 风速单位切换
- 关于页

---

## 4. 7 天预报与 24 小时预报原型说明

### 4.1 24 小时预报
- 横向滚动展示
- 显示时刻、天气图标、温度
- 保持现有布局不变

### 4.2 7 天预报
- 以卡片内纵向列表形式展示
- 每一行包含：
  - 星期 / 今天
  - 月日
  - 图标
  - 天气描述
  - 高低温

说明：
- 当前已修复“所有日期都显示为周三”的问题
- 星期现在根据真实日期计算

---

## 5. 当前组件状态

### 5.1 已落地组件
- 主天气头部
- 当前天气卡片
- 24 小时预报列表
- 7 天预报列表
- 城市选择卡片项
- 搜索框
- 设置弹窗表单项
- 错误态页面
- 保存并重试按钮

### 5.2 组件设计原则
1. 尽量复用现有样式
2. 不因接入真实 API 改动整体布局
3. 错误态也保持统一视觉风格
4. 城市搜索结果与已添加城市列表保持一致的卡片语言

---

## 6. 与旧原型文档的主要差异

| 旧原型 | 当前实际 |
|--------|----------|
| 有 Splash Screen 独立设计 | 当前重点不在启动页原型 |
| 位置管理与搜索页面分离 | 当前合并到城市选择页 |
| 设置页包含主题/单位等完整能力 | 当前设置弹窗主要是刷新间隔与 API 参数 |
| 以静态信息为主 | 当前已围绕真实接口与错误恢复做交互增强 |
| 默认城市示例为北京 | 当前默认城市为广州 |

---

## 7. 后续原型优化建议

1. 为城市空状态与错误状态补充更明确文案规范
2. 为 API 配置弹窗补充输入校验说明
3. 补充桌面小部件视觉稿
4. 若后续增加主题切换，再补充深浅色完整设计稿
